# Example data of the tutorials

The tutorial notebooks read three postcode areas of a pylovo run for all of Bavaria (LV version `1`, MV variant
`1`) from the database of your `.env`. Without a database, or without these areas in it,
`pylovo.examples.TutorialData` reads them from this folder instead.

| Area | Settlement type | Grids | Typical grid |
| --- | --- | --- | --- |
| 80805 München (Schwabing-Freimann) | urban | 50 | 2/13 |
| 85256 Vierkirchen | semi-urban | 26 | 2/1 |
| 85307 Paunzhausen | rural | 15 | 1/6 |

The three are typical of their settlement type among the 2,064 Bavarian postcode areas of the run: close to the
median in grids per area, buildings per grid, station rating, feeder length per building, house distance and
households per building.

## Files

The GeoPackages are zipped, so every file stays below the 1000 kB limit of the pre-commit hook; GDAL reads them
in place (`/vsizip/`).

| File | Content |
| --- | --- |
| `manifest.json` | version, generation parameters, the areas, their typical grids and voltage chains |
| `<plz>.gpkg.zip` | the map layers of `DatabaseClient.read_lv_layers` (EPSG:25832) |
| `<plz>_exclusions.csv` | buildings left out of the grids, with the reason |
| `nets/<plz>_<kcid>_<bcid>.json` | the pandapower net of the typical grid, with its validation power flow |
| `voltage_levels/<plz>_<kcid>_<bcid>.gpkg.zip` | HV grid, MV supply areas and the MV grid of the typical grid |
| `grid_summary.csv.xz` | key figures of all 86,721 grids of the run (three significant digits) |
| `postcodes.csv` | settlement type and density metrics of all postcode areas of the run |

## Version variants (`versions/`)

The versions tutorial compares version `1` with four variants that change one setting each. They were generated
for the three areas in a separate database with `docs/scripts/make_tutorial_versions.py`. A fifth version with the
settings of version `1` reproduced its 91 grids and every line length exactly, so the variants differ from version
`1` by their setting alone.

| Version | Changed setting | Grids 80805 / 85256 / 85307 |
| --- | --- | --- |
| `1` | (the Bavaria run) | 50 / 26 / 15 |
| `tut-osm` | `USE_OPEN_TRANSFORMER_POSITIONS: True`: existing stations from OSM and LoD2 | 42 / 23 / 14 |
| `tut-reach` | `MAX_GREENFIELD_TRAFO_DISTANCE: 1500` instead of 1000 m | 50 / 24 / 13 |
| `tut-cabin` | `HOUSE_CONNECTION: cabinet` instead of `joint` | 50 / 26 / 15 |
| `tut-large` | `TRANSFORMER_MAPPING` one rating step larger: rural 400/630, otherwise 630/800 kVA | 37 / 21 / 13 |

Each variant folder holds a `manifest.json` with its generation parameters, plus `grid_summary.csv` and
`postcodes.csv` for the three areas. The map layers are kept for 85256 only: stations and lines in
`85256.gpkg.zip`, and the supplying grid of each building in `85256_buildings.csv`. The building footprints are
those of version `1`. `TutorialData(plz, version_id="tut-osm")` reads a variant when the database lacks it.

## Regenerating

From the repository root, with a `.env` that points to a database with the Bavaria run and the HV grid downloaded
once (`pylovo-viewer fetch etrago`); the export only reads the database:

```bash
uv run --extra plots python -c "from pathlib import Path; from pylovo.examples import export_example_data; export_example_data(Path('data/examples'))"
```
